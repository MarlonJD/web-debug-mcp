# Repeated repair comparison protocol

The original40conversations remain frozen. This follow-up tests actual repairs to three small independently maintained upstream examples, with withheld controlled defects. It is not a comparison on large production applications or naturally discovered upstream bugs. All adaptations, source commits and licenses are recorded before dispatch.

Each app has3fresh independent conversations for each of gpt-6-astra and gpt-6.1-sol, with model_reasoning_effort=max, under3arms: ordinary Playwright/framework tooling; released Web Debug0.12.0 at f96443f481c0f394ff552edbbb44c2d7e969c927; and the unreleased working source. There are54scheduled conversations. The ordinary baseline supplies a reusable collector rather than requiring repeated boilerplate. It imports no Web Debug code; Next's own development endpoint remains an ordinary framework surface. Thus native means no Web Debug plugin/MCP, not a prohibition on every use of the MCP protocol.

The task is to reproduce, diagnose and repair a user-visible defect, retain baseline evidence and a reusable flow, and perform at least3complete post-fix attempts under the same acceptance checks plus relevant regressions. Solutions/pristine sources/seed details/oracles are absent from model workspaces. The model may inspect the defective application. Authorization boundaries are prompt-enforced and audited from commands; they are not a filesystem secrecy claim.

Every model starts an ephemeral fresh conversation with unrelated plugins/apps/memory/web search disabled. No result can influence selection or ordering. Repetitions rotate arm order; app/model blocks are shuffled with seed20261014. Dispatch uses3workers and at most2Next instances. Each conversation has a10minute wall-time limit, including model/tool work. App warmup, independent grading and teardown are outside solver time. The machine is shared across concurrent trials; elapsed time is descriptive, not a controlled CPU-isolation measurement.

App/source/service settings are equal within each case, except the selected Web Debug/Vite bridge. Next uses an actual disposable local PostgreSQL instance, with a separate database per trial and an observable test-only reset route. Resets are authorized only for that disposable database. The exact Next root has no Vite marker. Private synthetic task input is in a designated operator file; operator reads/raw input are separate from public outputs and shareable artifacts. Pixel suppression, redaction leaks and missing evidence are scored separately from patch correctness.

Before model dispatch, independent black-box controls must reject every seeded app and accept every reference repair in3isolated runs; the prebuilt ordinary collector must pass the same positive flows3times. Public candidate MCP qualification must reproduce each seed, verify the reference through3post-fix attempts and read retained evidence without replay. Preflight failures are preserved separately and never counted as model outcomes.

After each model ends, the withheld ordinary browser grader exercises the repaired application in3fresh contexts with additional regression inputs. Its verdict does not use an MCP verification verdict or a model claim. Retain every scheduled outcome, including timeouts, execution errors, false claims, scope violations, missing reports and privacy failures. Do not rerun outcome-selected model trials. Infrastructure repair before dispatch is allowed; affected preflight records remain.

Report source repair correctness (independent oracle), normal completion, evidence completeness, privacy and task-scope adherence separately. Evidence-complete means a real baseline, a retained reusable flow, at least3actual post-fix executions, supported observations and appropriate regressions. Raw MCP attempts or executed native scripts/receipts support counts; a report field by itself does not. Unsupported or uncollected evidence remains unavailable/inconclusive.

Compare time/tokens only among normal, evidence-complete matched trials, while showing all scheduled failures in the main outcome table. Give matched denominators explicitly. Record input, cached input, uncached input and output usage from actual CLI turn.completed events; do not invent usage for censored runs. Tool-result byte counts include serialized outputs and are not token estimates. Count every rejected tool call regardless of whether the SDK or facade produced it. Report supplementary native tooling in MCP arms. Small paired medians and ranges are descriptive; make no statistical-significance or general superiority claim.

Freeze protocol/order/source/skills/dependency-lock/runtime/collector/oracle hashes before model calls. Store prompts, invocation settings, raw events, final text, submitted source/evidence, independent verdicts, timing, usage and cleanup identities. Close only command-owned browser/server processes and the disposable database when complete. Implementation remains unreleased; publication/installation is a separate task.
