# Add local fidelity, semantic diagnostics, and bounded lifecycle cleanup

Maintain this plan according to [`../../PLANS.md`](../../PLANS.md). This is the implementation and release contract for Web Debug MCP `0.3.0`.

## Purpose / Big Picture

Complete the local flows that exposed the current `0.2.0` boundaries without attaching to a developer's daily browser profile or weakening the loopback-only posture. A caller must be able to open one explicitly approved self-signed HTTPS loopback origin, seed an isolated Chromium context from a bounded disposable-auth fixture, diagnose computed accessibility roles and names, use returned semantic locators directly, preserve named state checkpoints through a long role handoff, and run the same scenario across a bounded desktop/mobile matrix. Stdio EOF, transport close, an idle TTL, and an explicit cleanup command must release only registry-verified Web Debug processes.

The end-to-end proof is one deterministic local flow covering strict-versus-opt-in TLS, seeded and unseeded auth, accessible-name drift, route/role/count/CTA/status checkpoints, a mobile-only failure signature, desktop/mobile post-fix verification, and clean process exit. Existing vanilla, React/Vite, Next, Safari, debugger, replay, redaction, and adaptive-verification behavior remains locally verified. Safari remains CSS-only for actions/probes and explicitly unavailable for computed accessibility trees, semantic locators, TLS bypass, auth seeding, and viewport matrices. Auth-seeded sessions never create screenshots because screenshot pixels cannot be truthfully redacted.

The release is `0.3.0`. Package, lockfile, server metadata, plugin manifests, marketplace metadata, documentation, tag, GitHub release, and installed Codex plugin must agree. The bundled MCP runtime is pinned immutably to `github:MarlonJD/web-debug-mcp#v0.3.0`; this work does not install a CA, add a browser-wide certificate flag, use a daily profile, publish to npm, or add a public MCP tool.

## Surprises & Discoveries

- Chromium launch mode creates its context without `ignoreHTTPSErrors`, but the adapter derives `baseOrigin` only after the first `goto`. Because Playwright certificate ignoring is context-wide, simply setting the option would trust every request in that context before Web Debug had established an approved origin.
- Installed Playwright Core `1.62.1` provides context HTTP routing, `BrowserContext.routeWebSocket`, `serviceWorkers: "block"`, semantic locators, `Locator.ariaSnapshot()`, and the CDP Accessibility domain. These are sufficient for a same-origin TLS guard and computed diagnostics without a new dependency or a global Chromium flag.
- Safari's current new-session payload sets `acceptInsecureCerts: true`, contradicting the intended strict default. `0.3.0` must omit it or set it to `false`, and Safari must reject the loopback TLS bypass option.
- The current adapter exposes actions and snapshots but no authoritative live locator probe. Current checks infer state from a bounded DOM text summary, so they cannot truthfully decide implicit role/name, enabled, checked, count, or exact-text conditions.
- Current check groups are each capped at 20 and attempt summaries call `slice(0, 20)`. Representative conflict comparison therefore risks comparing a truncated set rather than every accepted decisive observation.
- Repeated Chromium attempts currently replace `session.adapter`. A viewport matrix built on that path would mutate the canonical manual session and could return many full evidence bundles. Matrix execution instead needs short-lived candidates that never enter the session map.
- The comparison demo already uses `1440x900` and `390x844`, but its per-viewport managers are private orchestration. The public scenario contract is still single-viewport and cannot express that only mobile should reproduce a responsive failure.
- The stdio process only handles SIGINT/SIGTERM. Session leases track mutating session work, but read-only/non-session MCP requests are not process-wide activity, and stdin EOF/close, transport close, startup-with-no-session idle time, and external cleanup races are uncovered.
- A safe cleanup registry needs cross-process serialization, not only atomic JSON replacement. Cleanup must win an idle-to-terminating transition under a per-instance lock, and every later request must see `terminating` and be rejected before work starts.
- The live TLS/auth smoke cannot place storage state in an unrelated temporary directory while the product requires project-root containment. The smoke must create a complete temporary project root and keep the auth fixture inside it.
- Implementing evidence bounds exposed that Next request-insight payloads can exceed the 96 KiB evidence limit; pruning must retain compact request traces and the linked terminal POST span rather than dropping decisive server-action linkage.
- Closing a session must purge private scenarios and evidence references without deleting screenshot artifacts that a caller may still be inspecting; artifact deletion is reserved for failed startup/command-owned fixture teardown.
- Safari WebDriver executes JavaScript strings, so the probe expression must not contain TypeScript-only casts even though the adapter itself is TypeScript.
- The bundled plugin validator could not run because its host Python environment lacks the `yaml` module (`ModuleNotFoundError: No module named 'yaml'`); all five plugin/marketplace JSON files parse successfully with a native Node check, so validator evidence remains candidate-only.
- Screenshot redaction currently protects serialized text and handles, not pixels. The only honest default for an auth-seeded context is to suppress screenshot creation entirely.
- The current worktree is intentionally not clean: this plan is new and the registry row is modified. Baseline verification must record those expected changes rather than claiming a clean tree.
- The MVP plan remains active with approved external CDP evidence pending, while the harness still says the repository owns no release action. Before `v0.3.0`, move the external-CDP candidate to bounded follow-up, complete the locally finished MVP plan, and update harness release/rollback authority without claiming production readiness.
- `npm pack --dry-run` cannot prove the installed binary. Release verification must create the real tarball, install that exact file into a fresh prefix, and exercise its stdio and cleanup entry points.
- Codex CLI `0.146.0` documents marketplace refresh plus `plugin add`, but has no separate update subcommand. The release workflow must prove whether `plugin add` replaces the installed snapshot by comparing before/after JSON and must retain an exact rollback path.

## Plan of Work

### Milestone 1: Replace the public browser/scenario contract and add pure aggregation

Define one strict `BrowserLocator` union: CSS `{ kind: "css", value }`, role `{ kind: "role", role, name? }`, text `{ kind: "text", text }`, label `{ kind: "label", text }`, and test id `{ kind: "testId", value }`. All strings are literal/exact; no regex or `exact` toggle is accepted. Click/fill/wait use `locator`; the old `selector` fields are removed from Zod, domain types, adapters, replay, hashes, fixtures, tests, scripts, docs, and examples in the same change. Legacy selector inputs must fail schema validation. Navigation/reload remain unchanged.

Add `BrowserAdapter.probe(locator, properties, context)`. Properties are the unique requested subset of `count`, `visible`, `enabled`, `checked`, and `text`; the result returns one fresh timestamp/provenance plus exact property values and warnings. Chromium resolves Playwright locators and probes them live. Safari resolves only CSS and returns `LOCATOR_STRATEGY_UNAVAILABLE` for every non-CSS kind. Observable waits poll `probe` under the remaining deadline; they do not sleep without a named property/expected value.

Replace current `ScenarioCheck` variants with exact route and live locator facts: exact path/route, exact or containing locator text, exact count, visible, enabled, disabled, and checked. Preserve `noConsoleErrors` as a browser-observer check. Each group may contain up to the aggregate schema ceiling, but core expands failure, acceptance, regression, reset-ready, and checkpoint properties and rejects the whole scenario when the single `MAX_DECISIVE_OBSERVATIONS` total exceeds 64. Evaluation and representative recapture compare all accepted observations in canonical order; no `slice` or serializer cap is allowed before the conflict decision. If the full decisive set cannot fit the final bounded result after optional pruning, return a stable bounded/inconclusive result rather than omit a verdict input.

Define named checkpoints with exact unique names and declared order. `offset` is the zero-based completed-action boundary `0..actions.length`: offset `0` is captured after initial scenario navigation and before the first action; offset `k` is captured immediately after `actions[k - 1]`; offset `actions.length` is the final boundary after the last action. Offsets are strictly increasing, the final boundary occurs at most once, and an empty action list permits only offset `0`. Each checkpoint holds ordered, uniquely named probes plus an optional exact route observation.

Define named unique viewport entries and optional `failureViewports` as exact viewport names. Omission means the complete failure signature must reproduce at every viewport. A mobile-only bug uses `failureViewports: ["mobile"]`: baseline is reproduced only when the full signature matches on mobile and is absent on every non-listed viewport; checkpoints must still be decisive everywhere. Post-fix always requires acceptance/regression/checkpoints to pass and the complete failure signature to be absent at every viewport. Never infer failure scope from width.

Implement pure, deterministic aggregation in core: the complete probe/check observation array yields a viewport verdict; ordered viewport verdicts yield an attempt; attempt quorum yields a phase; baseline plus post-fix yields the final result. Adapters never decide outcomes. Per-viewport checkpoint expectations compile only when every decisive baseline execution for that viewport agrees exactly on the full canonical checkpoint observation set. Consensus is stored separately per viewport and compared only with that viewport post-fix. Missing, stale, mixed, or unavailable values make the phase inconclusive.

### Milestone 2: Add guarded Chromium TLS/auth, live probes, and bounded accessibility diagnostics

Parse and validate the raw target URL in core before browser/context creation. For TLS bypass require HTTPS, a literal loopback host accepted by existing policy, Chromium launch ownership, no CDP attach, no Safari, and no remote opt-in. For either TLS bypass or auth seeding, compute one `approvedOrigin` before adapter start and pass it privately with the validated start settings.

Chromium creates the context with `ignoreHTTPSErrors: true` only for explicit TLS bypass and `serviceWorkers: "block"` for either elevated mode. Before creating the first page, install a context request route that permits only the exact approved HTTP(S) origin and aborts every other network origin, including another loopback port; install a context WebSocket route that permits only the corresponding exact secure/insecure WebSocket host/port and closes every other socket without connecting; install a context page listener that retains the single owned page and immediately closes every popup/secondary page. Validate every navigation response/final URL again so redirect escape is a stable error. No request, redirect, popup, WebSocket, or service worker may escape before policy is active. Strict Chromium omits `ignoreHTTPSErrors`; Safari omits or sets `acceptInsecureCerts: false` and rejects the bypass option.

For `authFixture: { kind: "playwrightStorageState", path }`, require isolated launch-owned Chromium and a loopback target. Resolve the canonical project root and candidate, require containment, reject a final symlink, then open with read-only/no-follow flags. Use `fstat` to require a regular file and enforce the byte cap, read at most `MAX_AUTH_STATE_BYTES + 1` from that same descriptor, `fstat` again, and reject identity/size/mtime changes; never reopen by path. Parse a strict top-level `{ cookies, origins }` object. Reject extra top-level fields, IndexedDB/credentials, extra cookie/origin/item fields, non-finite values, duplicate cookie or storage keys, and every bound violation.

Normalize the approved host/origin once. Each cookie domain, after one optional leading dot is removed, must equal the approved loopback hostname; each storage origin must equal the approved origin including scheme and port. Cookie paths start with `/`; cookie expiry is session-only (`-1`) or no more than 900 seconds in the future; secure/same-site combinations must be valid for the target. Pass only the parsed private object to every ephemeral context. Register the fixture path plus every cookie/local-storage name and value in the session secret set before adapter startup, use static bounded errors that never echo parsed data, and expose only `authFixture: "seeded-disposable" | "none"`.

When auth is seeded, force `captureScreenshot` false in manual and representative capture before calling the adapter, create no image file, and return a warning that screenshot pixels are not claimed redacted. Continue normal structured redaction for DOM, console, debugger, framework, error, replay, hash, and result fields.

Add bounded optional accessibility diagnostics to Chromium capture using supported Playwright/CDP data. Return computed role, exact computed name, selected state, depth, ignored reason where useful, truncation, and at most 128 normalized nodes; never return raw backend objects. Generate at most 32 exact locator suggestions, live-validate each through `probe`, include `matchCount`, and set only `uniqueAtCapture: true` when the count at that capture is one. Prefer exact role/name, then test id, label, and bounded CSS when reliable. The full AX tree may be omitted or truncated under its optional child deadline; semantic actions/checks/checkpoints remain authoritative because they call `probe` directly. Safari reports computed tree and semantic suggestions unavailable.

### Milestone 3: Run checkpointed viewport matrices without touching the canonical session

Retain validated TLS/auth/origin/private start settings in core. For every phase/attempt/viewport execution unit, create one fresh Chromium adapter with that viewport, run reset/navigation/actions/checkpoints/final checks, and close it in `finally`. Execute units sequentially under the shared phase deadline and stop starting new units when the remaining deadline cannot begin one. At most 20 units run per phase. Never assign a candidate to `session.adapter`, never mutate canonical session target/status/replay/observer buffers, and never reuse a candidate across viewports.

Return nested lightweight summaries: phase -> attempt -> viewport. A viewport summary carries its name/size, verdict, observation/checkpoint counts, failing or unavailable observation references, full-observation digest, elapsed/reset facts, and bounded warnings—not a duplicated DOM/AX/framework/replay bundle. Keep at most one 96 KiB representative evidence bundle for baseline and one for post-fix across the entire result. Select a failed or unavailable viewport before a passing viewport; for a reproduced baseline, prefer a requested failure viewport. Capture representatives only when a phase needs diagnosis or authoritative confirmation, then re-run the complete probe/check set and compare the full canonical arrays/digests without slicing.

Apply deterministic failure-first pruning only after final verdicts exist: remove optional React/Vite/Next/AX detail, then optional logs/network/replay, then nonessential passing detail. Preserve scenario definitions, aggregate counts, viewport identities/order, failing/unavailable references, checkpoint consensus/digests, outcome, and warnings. If those decisive summaries still exceed 256 KiB, return `inconclusive` with `RESULT_LIMIT_EXCEEDED`; do not silently turn a larger truth set into a smaller passing one.

All locator actions, waits, probes, route reads, snapshots, and optional captures receive the shared abort signal and absolute deadline. Adapter timeouts are the smaller of their local ceiling and remaining deadline. Cancellation/timeout closes the ephemeral candidate before another unit starts and yields unavailable/inconclusive unless a prior evidence-backed phase verdict is already final.

### Milestone 4: Add a secure process registry, request tracking, idle TTL, and cleanup CLI

Create a per-user registry directory under the OS temporary root named `web-debug-mcp-registry-<numeric uid>`. Before use, `lstat` it, reject symlinks/non-directories/wrong owner/group-or-world mode, create it as `0700` when absent, and create record/temp/lock files as `0600` with no-follow/exclusive flags. Abort registry/cleanup operations when more than 128 directory entries or 64 valid records exist; never partially scan and signal. Only filenames matching the exact UUID-derived `<instance>.json`, `<instance>.lock`, and `.tmp` patterns belong to cleanup. Unknown files and directories are reported and untouched.

Each bounded record contains schema/version, instance UUID, PID/PPID, package version, canonical Node executable and package entry identity, OS start identity, `startedAt`, `lastActivityAt`, `idleSince`, `heartbeatAt`, `idleTtlMs`, `activeSessionCount`, `activeRequestCount`, `busy`, and lifecycle state `idle | running | terminating`. It never contains URLs, project roots, auth/evidence paths, environment values, or secrets. Every state change uses temp-file-plus-rename while holding that instance's exclusive lock. Heartbeat every 15 seconds and all timers are unref'd.

Wrap every MCP tool handler, including project detection, status, capture, close, and failures, in process-wide request accounting. Request start acquires the instance lock, rejects `terminating`, increments `activeRequestCount`, marks running/busy, and cancels idle expiry. Request completion decrements in `finally`, updates activity, and, when sessions and requests are both zero, atomically enters idle and sets `idleSince`. Session start/close updates `activeSessionCount` under the same lock. The default five-minute TTL arms at server startup even if no session is ever created and re-arms whenever the process returns to zero sessions/requests. `WEB_DEBUG_IDLE_TTL_MS=0` disables auto-exit; invalid/out-of-range positive values fail startup with a static error. TTL expiry rechecks locked state/counts, changes idle -> terminating, rejects new requests, closes sessions/transport once, removes only its own registry files, and exits naturally.

On Linux, identity verification uses `/proc/<pid>/stat` start ticks plus `/proc/<pid>/exe`, uid, and NUL-delimited cmdline. On Darwin, use spawned `ps` with explicit PID and fields for start time, uid, and full command, plus the canonical expected executable/package entry. No shell or substring process scan is used. If fields are unavailable, malformed, changed, or the platform is unsupported, cleanup skips and reports the record; it never signals.

`web-debug-mcp cleanup` removes dead records and terminates only registry records that are already TTL-expired, zero-session, zero-request, non-busy, and identity verified. `cleanup --all-idle` relaxes only the TTL-age requirement, not ownership or zero-activity requirements. Cleanup acquires the per-instance lock, revalidates identity and record, atomically writes `terminating`, and releases. New target requests must then reject. Immediately before SIGTERM, reacquire/read and reverify state, counts, PID/start/executable/entry; after the two-second grace, immediately before SIGKILL do the same again. Never signal after identity/state drift. Remove a dead record/lock/temp only when its exact matching identity is dead and the path is an owned matching registry filename. A stale lock is removable only when the matching recorded process is verified dead.

## Idempotence and Recovery

Plan/docs/source/test changes are safe to rerun. Do not create/switch branches, reset user changes, delete existing tags/releases, or publish to npm. Runtime-generated project roots, certificates, auth fixtures, package/install prefixes, browser profiles, screenshots, registries, and fixture servers are command-owned and removed only by exact handles in `finally`/signal traps.

Ephemeral matrix candidates never replace the canonical adapter, so a failed start/run/capture closes only that candidate. Checkpoint consensus commits to the scenario only after a decisive baseline phase for every viewport. Cancellation stops new units, waits/closes the current candidate within bounds, and preserves already-computed summaries without upgrading them to success.

Auth reads use an already-open descriptor; a path swap after open cannot redirect the read, and any observed descriptor mutation fails closed. Elevated origin routing is installed before the first page; if any guard cannot be installed, close the context and fail start. Auth-seeded screenshot suppression happens before adapter capture, so recovery never needs to locate/delete a secret-bearing screenshot.

Registry writes and state transitions are per-instance locked and atomic. Malformed, oversized, capped, wrong-owner/mode, symlink, identity-mismatched, active, busy, or unverifiable records are skipped/reported. Cleanup never broadens scope after a failure. A process that dies between checks is treated as dead/stale; a process whose identity changes is never signaled. Unregistered legacy processes require manual user-owned handling outside this release.

Release writes begin only after local verification and exact intended commit review. If push fails, do not tag. If tag push fails, keep the local tag at the exact SHA and retry only that push.
