# Astra and Luna skill evaluation

The requested Astra max, Astra ultra, and Luna max comparisons are complete. The revised skills reduce some tool-input mistakes, but these trials do not establish generally better output quality. Longer runs tie on repair/authoring correctness, time and action costs vary by task, and candidate test preparation still contains substantive assertion and source-coverage defects. A passing repair grade is not a complete quality score: one revised Luna browser answer makes an unsupported server-outage claim despite a correctly verified repair.

Runtime improvements are independently verified: the 13-tool catalog is 62.7% smaller in serialized JSON bytes, selective captures avoid unrequested enrichment, and the local runtime checks pass. These measurements do not imply a measured token, billing, or latency reduction.

## What changed and why

The runtime supplies capabilities that model reasoning cannot replace: an owned browser session, same-origin enforcement, actual browser observations, redaction, replay, and independent verification. These remain model-independent. No Astra-specific server branch or additional public tool was introduced.

| Part | Change | Intended benefit |
| --- | --- | --- |
| `web-debug-workflow` | Narrow routing; conditional binding recovery; summary-first capture; valid recording example; stop after the requested acceptance is verified | Less unnecessary browser work, schema guessing, and repeated verification |
| `webmcp-tool-authoring` | Preserve earlier authorization; reuse the product operation; runnable bounded payment example with cancellation and registration lifetime | Correct local implementation with fewer redundant approval requests |
| `manual-parity-qualification` | Complete source-backed candidate preparation within existing authority; preserve the separate approval boundary for an official baseline | Useful preparation without self-approval or avoidable pauses |
| Evidence collection | Collect requested enrichment only; distinguish fresh, stale, unavailable, not detected, and not collected; preserve partial cursor knowledge | Smaller, truthful evidence that does not turn omitted observations into negative findings |
| Schema catalog | Reuse supported Zod schema definitions; preserve concrete input/output validation and 13 tools | Lower repeated schema volume |
| Evaluation | Artifact-bound run records, independent product/native checks, complete failure denominators, and explicit reviewer decisions | Reproducible evidence instead of assertions about skill wording |

The three isolated workstreams are routing/native repair (12 cells per setting), real browser repair (12), and authority/ambiguity (8). CLI requests record the exact requested model and accepted reasoning setting; the JSONL stream does not independently attest the provider's served-model identity. Ambiguous mutation has an external one-attempt ledger and unavailable readback; the expected outcome is explicitly inconclusive.

Broader claim accuracy is reviewed separately: that field does not cover every unsupported failure or environment inference. Per-task medians show latency, tool calls, input/cached/output tokens separately; missing usage is null. Cross-task sums would mix different difficulties and are not a model speed ranking. Two repetitions provide descriptive evidence, not statistical significance.

## Opportunities identified by the follow-up

The drawer trials reveal a capability gap rather than simply excessive verification: existing recorded checks can establish a position marker or count, but do not express the entire viewport/backdrop/CTA geometry contract. Models therefore need additional measurements, and sometimes guess an unsupported failure-signature shape. A bounded geometry predicate within the existing record/verify tools is a future implementation hypothesis; this evaluation does not measure it. The frozen runtime was not changed during the comparison.

Generic PNG resource exports also repeatedly exceeded the client text/image transport path, while native image blocks remained usable. A future workflow refinement could prefer images already returned natively and use the exact advertised server name. This was not inserted into the evaluated skill midway through the runs, and no benefit is claimed for an untested revision.
