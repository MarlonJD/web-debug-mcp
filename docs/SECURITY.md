# Security

`web-debug-mcp` is a local debugging tool that can observe and control a running browser. The default posture is least privilege for local development: explicit target selection, loopback-only URLs, isolated launch mode, bounded evidence, and redaction.

## Sensitive data policy

The core adapter does not collect cookies, authorization headers, browser storage, or raw response bodies by default. It does collect URLs, console text, debugger locals, DOM text, and screenshot pixels because those are required for debugging; each is bounded and redacted before returning to the MCP caller. Callers must use disposable local credentials and synthetic data for live sessions.

The Next adapter reads the development server’s MCP metadata surface over the already selected local origin. It does not authenticate to a remote Next server or execute arbitrary Next runtime tools; only the allowlisted metadata tools are called. When `get_logs` returns a path, the adapter resolves it, requires the file to stay inside the detected project root and retain the expected Next development-log basename, then reads only a bounded tail and redacts it. The Vite plugin similarly exposes only bounded module metadata on the local dev server and is not intended for production.

The redaction layer is defensive, not a guarantee of secrecy. New adapters must document every new field and add a regression test before exposing it through `EvidenceBundle`. Auth-seeded sessions intentionally create no screenshot file or resource handle; structured text and metadata remain defensively redacted. Fill and select values are private live-session inputs and public replay replaces both with a marker.

Chromium attach mode installs CDP `Fetch` interception only on the selected target, but popup-first requests can arrive before Playwright exposes a frame. The fail-closed fallback therefore uses a `BrowserContext` route for the lifetime of the session: framed requests from sibling pages and frame-less non-document requests fall through, while every frame-less document request is aborted. Playwright disables HTTP cache while that context route is installed, so attached sibling pages can observe changed cache behavior even though their DOM and React runtime are not injected or navigated. Close the session to remove the route and restore normal context behavior.

Recorded scenarios retain raw fill/select values only in the live session's private memory. Public scenarios, contract hashes, attempt summaries, build references, errors, replay frames, screenshots, and representative evidence scrub action values before serialization, including values appearing in dynamic DOM ids, nested framework data, details, and artifact handles. Screenshot files remain under the owning session's temporary directory; if redaction would collide with a path, only the serialized handle is set to null and the original file is not copied or moved. The executable URL is private and the public scenario URL removes its query. The contract hash is an ordinary SHA-256 of the sanitized contract; it is not an authenticated build identity and cannot support cross-session reuse. Closing purges private scenarios, retained evidence, auth state, raw start settings, secrets, and target identity before removing the managed session.

## Abuse and recovery

The server binds to MCP stdio and the browser adapter uses explicit local targets. Do not expose a CDP endpoint or a future daemon on a non-loopback interface without a separate authentication and threat-model decision. If a session is attached to the wrong browser, close it immediately, discard the evidence, and restart with launch mode and an isolated profile.

Repository-local boundary review and deterministic regression tests cover origin navigation, auth-state containment, redaction, response budgets, artifact identity, session teardown, and process ownership. No external penetration test or production hardening claim has been performed; this remains a local development tool.
